# 00. はじめに

## この教材について

この教材は、Javaの文法学習を終えた人が「実務のコードを読める・直せる・拡張できる」ようになるための練習場です。題材は、収入と支出を記録するデスクトップの家計簿アプリです。

文法の学習と実務のあいだには、次のようなギャップがあります。

- 処理が**複数のクラスにまたがっていて**、どこから読めばいいか分からない
- 「なぜこう設計したのか」という**判断の理由**が分からない
- 例外処理・入力チェック(バリデーション)・SQLなど、**教科書のサンプルには出てこない実務コード**に免疫がない

この教材では、完成品のアプリを「読む」ところから始めて、バグを「直し」、最後に機能を「作る」ことで、このギャップを順番に埋めていきます。

## 対象者と前提知識

次の文法・概念を(完璧でなくてよいので)ひととおり学習済みであることを前提にしています。

変数と型 / 制御構文 / クラスとインスタンス / 継承とインターフェース / コレクション(List・Map) / 例外処理(try-catch) / ラムダ式の基礎

SwingやSQL、JDBCの知識は**前提にしません**。登場したときに読み方を案内します。

## 3つのPhaseの進め方

1. **Phase 1 読む**([01_読解マップ.md](01_読解マップ.md))
   完成版(`main` ブランチ)のコードを、ガイドに沿って読みます。アプリ全体の地図を頭に入れ、「支出を1件登録する」という処理を画面からデータベースまで追いかけます。
2. **Phase 2 直す**([02_バグ修正演習.md](02_バグ修正演習.md))
   バグ入りの `exercise/bugs` ブランチに切り替えて、実務風のバグチケット5件に取り組みます。症状の再現→仮説→検証→修正→再発防止テスト、という実務の流れをそのまま体験します。
3. **Phase 3 作る**([03_機能追加演習.md](03_機能追加演習.md))
   `main` に戻り、チケット形式の仕様書に基づいて機能を追加します。受け入れ条件を満たせばクリアです。

Phaseは順番に進めるのがおすすめですが、Phase 1を終えていればPhase 2と3はどちらから取り組んでも大丈夫です。

## 環境準備

必要なのは **JDK 21**(Javaの開発キット)だけです。ビルドツールのGradleはリポジトリに同梱されているため、インストール不要です。

### JDK 21のインストール

まだJDKが入っていない場合は、[Eclipse Temurin(Adoptium)](https://adoptium.net/temurin/releases/?version=21) から **JDK 21(LTS)** のインストーラを取得するのが手軽です。

- **Windows**: `.msi` をダウンロードして実行。インストール時に「Set JAVA_HOME variable」にチェックを入れると後がラクです。
- **macOS**: `.pkg` をダウンロードして実行。または `brew install --cask temurin@21`
- **Linux**: ディストリビューションのパッケージ(例: `sudo apt install openjdk-21-jdk`)

インストールできたか、ターミナル(コマンドプロンプト)で確認します。

```bash
java -version
# 「openjdk version "21.x.x"」のように21で始まるバージョンが表示されればOK
```

### エディタ・IDE

IntelliJ IDEA(Community版で十分)またはVS Code + Java拡張をおすすめします。Phase 2でデバッガ(プログラムを一時停止して変数を覗く道具)を使うので、IDEがあると学習がスムーズです。

## アプリを起動する

```bash
git clone <このリポジトリのURL>
cd kakeibo-tutorial
./gradlew run        # Windowsの場合: gradlew.bat run
```

- 初回はGradle本体とライブラリのダウンロードが走るため、数分かかることがあります。2回目からはすぐ起動します。
- 初回起動時に `./data/` フォルダにデータベースファイルが自動作成され、カテゴリ8種類と直近3ヶ月分のサンプル取引が投入されます。
- データを最初からやり直したくなったら、アプリを終了して `data` フォルダごと削除すれば、次回起動時にまた初期データが入ります。

## まず10分、アプリを触ってみよう

コードを読む前に、**このアプリが何をするものか**を体で覚えてください。以下をひととおり試してみましょう。

- [ ] 取引一覧を眺める。下部のステータスバーに件数と収入・支出の合計が出ていることを確認する
- [ ] 上部のフィルタで年月を選ぶ → 一覧と件数が変わることを確認する
- [ ] 区分を「収入」にする → 給与・賞与だけが表示される
- [ ] 「登録」ボタンから今日の支出を1件登録してみる(例: 食費 500円 メモ「ジュース」)
- [ ] 登録した取引を選択して「編集」→ 金額を変えて保存 → 一覧に反映されることを確認する
- [ ] その取引を「削除」する
- [ ] メニュー「カテゴリ管理」で新しいカテゴリ(例: 旅行)を追加する → 取引登録の選択肢に現れることを確認する
- [ ] 「食費」カテゴリを削除しようとしてみる → 「使用中のため削除できません」と案内されることを確認する
- [ ] メニュー「月次集計」で先月を選ぶ → 収支とカテゴリ別の構成比を眺める
- [ ] 金額の入力欄にわざと「abc」と入れて保存してみる → どんなエラーメッセージが出るか観察する

「エラーを出そうとして触ってみる」のは、これからコードを読むうえでとても良い準備運動です。どこかで誰かがそのエラーを処理しているはずだ、と考えながらPhase 1へ進みましょう。
