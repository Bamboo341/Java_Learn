# 04. 大量データ投入(性能検証用)

このドキュメントは、**5万件のダミー取引**をデータベースに投入する手順です。次の場面で使います。

- **BUG-05**(Phase 2)の症状「月次集計を開くと固まる」の再現
- **T-103**(Phase 3)などで、データが多くても動作が破綻しないことの確認

## 事前準備

- **アプリを終了してください。** このアプリのDB(H2の組み込みモード)は同時に1プロセスしか開けないため、アプリ起動中にシェルを開こうとすると「Database may be already in use」というエラーになります。
- 投入するダミーデータは、メモ欄が「負荷試験データ」で統一されています。あとで一括削除できるので、既存データと混ざっても心配ありません。

## 1. SQLシェルを起動する

H2に付属するSQLシェル(SQLを直接実行できる対話ツール)を、Gradleタスクで起動します。

```bash
./gradlew dbShell --console=plain      # Windowsの場合: gradlew.bat dbShell --console=plain
```

`sql>` というプロンプトが出れば接続成功です。試しに現在の件数を見てみましょう。

```sql
SELECT COUNT(*) FROM transactions;
```

終了するときは `exit` と入力します。

## 2. 5万件を投入する

以下のSQLを丸ごとコピーして `sql>` プロンプトに貼り付け、Enterで実行してください(数秒かかります)。

```sql
INSERT INTO transactions (transaction_date, amount, type, category_id, memo)
SELECT
    DATEADD('DAY', -MOD(X, 1095), CURRENT_DATE),
    100 + MOD(X * 37, 9900),
    'EXPENSE',
    CASE MOD(X, 3)
        WHEN 0 THEN (SELECT id FROM categories WHERE name = '食費')
        WHEN 1 THEN (SELECT id FROM categories WHERE name = '日用品')
        ELSE        (SELECT id FROM categories WHERE name = '娯楽')
    END,
    '負荷試験データ'
FROM SYSTEM_RANGE(1, 50000);
```

### このSQLのしくみ(読んでおくと勉強になります)

- `SYSTEM_RANGE(1, 50000)` は、1〜50000の連番(列名 `X`)を生成するH2の機能です。50000行のSELECT結果を作り、それをそのままINSERTしています。
- `DATEADD('DAY', -MOD(X, 1095), CURRENT_DATE)` — 今日から過去3年(1095日)の範囲に日付をばらまきます。
- `100 + MOD(X * 37, 9900)` — 100〜9,999円の金額を機械的に散らします。
- カテゴリは食費・日用品・娯楽の3つに順繰りに割り当てます。
- ※カテゴリ名を変更・削除している場合は、実在する支出カテゴリ名に読み替えてください。

### 投入結果を確認する

```sql
SELECT COUNT(*) FROM transactions;
-- 元の件数 + 50000 になっていればOK

SELECT COUNT(*) FROM transactions WHERE memo = '負荷試験データ';
-- 50000
```

確認できたら `exit` でシェルを終了します。

## 3. アプリで体感する

```bash
./gradlew run
```

- 一覧画面: 5万件を超えるデータでも一覧やフィルタがどの程度動くか触ってみてください(年月フィルタの選択肢が約3年分に増えているはずです)。
- **BUG-05の再現はこの状態で行います**(→ [02_バグ修正演習.md](02_バグ修正演習.md) のチケットBUG-05)。

## 4. ダミーデータを削除する

演習が終わったら、アプリを終了してから再度シェルを開き、一括削除します。

```bash
./gradlew dbShell --console=plain
```

```sql
DELETE FROM transactions WHERE memo = '負荷試験データ';

SELECT COUNT(*) FROM transactions;
-- 元の件数に戻っていればOK
exit
```

> **まるごとリセットしたい場合**: アプリを終了して `data` フォルダを削除すれば、次回起動時に初期データ(サンプル48件)から作り直されます。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `Database may be already in use` | アプリ(またはもう1つのシェル)がDBを開いています。先に終了してください |
| `Table "TRANSACTIONS" not found` | まだ一度もアプリを起動しておらず、DBが初期化されていません。先に `./gradlew run` で起動してください |
| 貼り付けたSQLが実行されない | 末尾のセミコロン(;)まで貼り付けられているか確認し、Enterを押してください |
