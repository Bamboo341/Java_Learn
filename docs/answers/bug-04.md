# 解答 BUG-04: 編集しても一覧が変わらない(再起動すると変わる)

> ⚠️ **ネタバレ注意** — このファイルは解答です。自分の仮説を立て、検証してから読んでください。

## 症状の整理

- 取引を編集して保存しても、一覧の表示が変わらない
- **アプリを再起動すると、変更後の内容になっている**
- 登録や削除は、直後に一覧へ反映される

## 調査の思考過程

1. **「再起動すると直っている」を最初に解釈する。** 再起動後に変更が見えている以上、**データベースには正しく保存されている**。つまりService→Repository→DBの保存経路は無実。問題は「保存後に画面を最新化する部分」に絞られる。この切り分けだけで、調べる範囲が一気にUI層だけになる。
2. 対照実験をする。「登録」した直後は一覧に反映される。「編集」だけ反映されない。ならば**登録と編集で、保存後の処理がどう違うか**を見ればよい。
3. `MainFrame.onRegister()` を見ると、ダイアログが閉じたあと `dialog.isSaved()` を確認し、`refreshFilterChoices()` と `reloadTransactions()` を呼んで一覧を読み直している。
4. `MainFrame.onEdit()` を見ると——ダイアログを表示したきり、**保存後に何もしていない**。

## 真因

`MainFrame.onEdit()` に、保存成功後の**一覧の再読込処理が欠けている**こと。

このアプリの一覧は「DBが変わったら自動で追随する」仕組みではありません。`reloadTransactions()` がServiceからデータを取り直し、`TransactionTableModel.setData()` が `fireTableDataChanged()` でJTableに「変わったよ」と通知して、はじめて画面が新しくなります。この呼び出しを忘れると、**データ(DB)は新しいのに表示(画面)は古いまま**という今回の症状になります。

## 修正内容

`src/main/java/com/example/kakeibo/ui/MainFrame.java`

```diff
         TransactionDialog dialog = new TransactionDialog(this, transactionService,
                 categoryService, selected);
         dialog.setVisible(true);
+        if (dialog.isSaved()) {
+            // 編集結果を画面に反映するため、一覧を読み直す
+            refreshFilterChoices();
+            reloadTransactions();
+        }
     }
```

登録側(`onRegister`)と同じ形に揃えるだけです。

## なぜテストをすり抜けたのか

「編集後に一覧が新しくなること」は、**画面(MainFrame)の振る舞い**そのものです。このアプリのテストはUI層についてはTableModel等のロジックだけを対象にしており、「ボタンを押したらフレームがモデルを読み直すか」という配線は単体テストの射程外でした。画面の配線ミスは、テストよりも目視確認・結合テストで見つかる種類のバグです。

## 再発防止(手動確認手順で代替)

このバグの自動テストはコストに見合わないため、リリース前の手動確認チェックリストとして残します。

```
【編集の反映確認】
1. 一覧で任意の取引を選び「編集」→ 金額を +1 して保存
2. その場で(再起動せずに)一覧の金額・ステータスバーの合計が変わることを確認
3. 念のためフィルタを切り替えても表示が一貫していることを確認
※ 登録・削除・カテゴリ名変更でも同様に「その場で反映」を確認する
```

なお、本質的に自動テストへ寄せたい場合は「画面の再読込をトリガーする処理」をフレームから分離する設計変更が必要になります(BUG-02の教訓と同じ方向性)。

## この型のバグから得る教訓

- **「データは正しいのに表示が古い」は頻出パターン。**まず再起動・再読込で直るかを試し、データの問題か表示の問題かを最初に切り分ける。
- Swing(に限らず多くのUI)は、**モデルが変わったことを通知されない限り再描画しない。**`fireTableDataChanged()` のような更新通知の仕組みを一度理解しておくと、この系統のバグに強くなる。
- 対照実験(動く機能と動かない機能の差分を見る)は、コードを全部読むより速いことが多い。
