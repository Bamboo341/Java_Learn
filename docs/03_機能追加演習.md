# 03. 機能追加演習(Phase 3: 作る)

このPhaseでは、チケット形式の仕様書に基づいて機能を追加します。実務の開発と同じく、**「受け入れ条件」をすべて満たしたらクリア**です。実装方法はチケットに書いてありません。Phase 1で作った地図を頼りに「どの層の、どのクラスに、何を足すか」を自分で設計してください。

所要時間の目安: 1チケット2〜6時間(★の数が難度です)

---

## 1. 準備 — mainに戻って作業ブランチを切る

Phase 2の作業内容と混ざらないよう、完成版の `main` から新しいブランチを切ります。

```bash
git checkout main
git switch -c feature/t-101     # 例: T-101用の作業ブランチ
./gradlew test                  # 出発点が全部緑であることを確認
```

## 2. 進め方のルール

- 着手前にチケットを読み、**変更が必要になりそうなファイルの一覧**を予想として書き出してください(答え合わせはansersで)。
- 機能を追加したら、**関連するテストも追加**してください。`./gradlew test` は常に緑を保ちます。
- 詰まったらAIに相談してOKです。ただし丸投げではなく「自分はこの層に置くべきだと考えたが、どうか」のように**自分の設計案を持って**相談してください。
- 完了したら `docs/answers/feature-10X.md` と照合します。**答えは一例**です。受け入れ条件を満たしていれば、違う実装でも正解です。

## チケット T-101: メモのキーワード検索 ★

**背景**
取引の件数が増えてきたユーザーから「『定期』とメモに書いた取引だけをまとめて見たい」という要望が届いた。現在のフィルタは年月・カテゴリ・区分のみで、メモの内容では絞り込めない。

**要件**
- 一覧画面のフィルタに、キーワード入力欄を1つ追加する
- 入力されたキーワードが**メモに部分一致**する取引だけを表示する
- 既存のフィルタ(年月・カテゴリ・区分)とは**AND条件**で組み合わせる

**受け入れ条件**
- [ ] キーワード「定期」で、メモに「定期」を含む取引だけが一覧に表示される
- [ ] 「2026年6月」+キーワード「定期」のように、他のフィルタと同時に使える
- [ ] キーワード欄が空のときは、メモによる絞り込みを行わない(従来どおり)
- [ ] 「100%」「その_他」のように `%` や `_` を含むキーワードでも、**その文字そのもの**として検索される(SQLのLIKEが持つ特殊な意味に注意)
- [ ] 検索条件のテストが追加されており、`./gradlew test` が緑

**対象外(やらなくてよいこと)**
- メモ以外(カテゴリ名など)を対象にした検索
- 大文字小文字の同一視、あいまい検索

## チケット T-102: フィルタ結果のCSVエクスポート ★★

**背景**
経理担当から「家計簿のデータをExcelで加工したい。画面で絞り込んだ結果をそのままCSVファイルに出せないか」という要望が届いた。CSVはカンマ区切りのテキスト形式で、Excelでそのまま開ける。

**要件**
- 一覧画面に「CSVエクスポート」の操作(ボタンまたはメニュー)を追加する
- 保存先は `JFileChooser`(ファイル保存ダイアログ)でユーザーが選ぶ
- **現在フィルタで表示中の内容**をCSVとして出力する
- 文字コードは **UTF-8のBOM付き** とする。ExcelはBOM(ファイル先頭の目印バイト)のないUTF-8を正しく認識できず日本語が文字化けするため。これは実務で頻出の落とし穴なので、あえて仕様に明記する
- 1行目はヘッダ行(`日付,区分,カテゴリ,金額,メモ`)とする

**受け入れ条件**
- [ ] フィルタで絞り込んだ状態でエクスポートすると、画面の表示内容と同じ行数・内容が出力される
- [ ] 出力したCSVをExcel(またはLibreOffice)で開いて、日本語が文字化けしない
- [ ] メモに「,(カンマ)」「"(ダブルクォート)」「改行」が含まれていても、列がずれない(CSVの標準的なクォート規則で守る)
- [ ] 区分は画面と同じ「収入 / 支出」の日本語で出力される
- [ ] CSV1行を組み立てるロジックにテストが追加されており、`./gradlew test` が緑(ヒント: 画面から切り離してテストできる場所に置くこと — Phase 2のBUG-02の教訓)

**対象外**
- 文字コードの選択UI、Excel形式(.xlsx)での出力、CSVのインポート

## チケット T-103: カテゴリ別の月次予算 ★★★

**背景**
「食費は月3万円まで」のように**カテゴリごとに予算を決めて、使いすぎに気づきたい**という要望。家計簿アプリの定番機能である。

**要件**
- 支出カテゴリに対して、月次予算(円・設定は任意)を設定・変更・解除できるようにする
- 月次集計画面のカテゴリ別テーブルに「予算」「実績」「残額」を表示する
- 予算を超過しているカテゴリは、ひと目で分かるよう**赤色で表示**する
- 予算が未設定のカテゴリは、予算・残額を空欄(または「-」)にする

**この課題の山場(スキーマ変更)**
予算を保存するには、データベースの `categories` テーブルに**列を追加する**必要がある。ここで問題になるのが、**すでに `data/kakeibo.mv.db` を持っている既存ユーザー**の存在だ。`schema.sql` を書き換えるだけでは、初期化済みのDBには反映されない(初期化は初回しか走らない)。既存DBをどうやって新しいスキーマに移行するか——方法を調べ、自分なりの方式を選んで実装すること。

**受け入れ条件**
- [ ] カテゴリ管理画面(または相当のUI)から、支出カテゴリに月次予算を設定・変更・解除できる
- [ ] 月次集計に予算・実績・残額が表示され、超過カテゴリが赤表示になる
- [ ] 予算未設定のカテゴリが混ざっていても正しく表示される
- [ ] **既存のDBファイルがある状態でアプリを更新しても、エラーにならず既存データが残っている**
- [ ] まっさらな状態(dataフォルダ削除後)の初回起動も正常に動く
- [ ] 予算まわりの業務ルールにテストが追加されており、`./gradlew test` が緑

**対象外**
- 月ごとに異なる予算、収入カテゴリの予算、予算の繰越、通知機能

## チケット T-104: 定期取引の自動計上 ★★★★(挑戦課題・任意)

**背景**
家賃やサブスクのように**毎月同じ日に発生する取引**を、毎回手入力するのは面倒だ。「定期取引」として登録しておけば、アプリが自動で計上してくれるようにしたい。

**要件**
- 定期取引のマスタ(名称・金額・収支区分・カテゴリ・毎月の計上日)を登録・編集・削除できるようにする(新しいテーブルが必要になる)
- アプリ起動時に、**当月分がまだ計上されていない定期取引**を自動で取引として登録する(計上日を過ぎているもののみ)
- 自動計上された取引は、通常の取引と同じように一覧・集計・編集・削除の対象になる

**この課題の山場(二重計上の防止)**
アプリは1日に何度も起動されるかもしれない。「その定期取引の当月分は計上済みか?」をどう判定するかがこの課題の核心である。判定方式を自分で設計すること(複数のやり方がある)。

**受け入れ条件**
- [ ] 定期取引(例: 家賃 82,000円 住居費 毎月1日)を登録できる
- [ ] 計上日を過ぎてから起動すると、当月分の取引が1件だけ自動で登録される
- [ ] **同じ月に何度起動しても、二重に計上されない**
- [ ] 月が変わって起動すると、新しい月の分が計上される
- [ ] 計上日がまだ来ていない場合は計上されない
- [ ] 二重計上防止のロジックにテストが追加されており、`./gradlew test` が緑

**対象外**
- 月次以外の周期(毎週・隔月・年次)、終了日や回数の指定、過去月への遡及計上、31日など存在しない日の高度な扱い(「月末日に丸める」程度の単純な仕様を自分で決めてよい)
